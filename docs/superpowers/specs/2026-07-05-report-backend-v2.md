# Spec W_backend (Round 1 클린) — 짤림 수정 + 그룹 순서

작성: 2026-07-05 · 개정 2026-07-05(fork 확정·리뷰 반영) · 구간 소유권 = `src/newsstore/enrich/report.py` + `config/topics.yaml` + `tests/test_report*.py`·`tests/test_topics.py`. **web/index.html 금지**(W_web 병렬). **frames.py 금지**(2층 프레임=Round 2 별도 스펙).

## 스코프 확정 (리뷰 후 축소)
리뷰가 프레임 재정의(2층)와 글로벌 프레임 제거를 fork로 escalate했고, 사용자가 확정: **2층 프레임 = Round 2 별도**(척추 수술·LLM-runtime), **글로벌 = 화면만 숨김(_market 입력·생성 유지 → 백엔드 무변경)**. 따라서 이 스펙은 **결정론 클린 2건만**: 짤림 수정 + 그룹 순서. (원안의 WB2·WB3 삭제.)

## WB1. 텍스트 짤림 수정 (문장 중간 절단 제거)
- **버그(실측 — 사용자 화면 2건)**: (a) 섹션 항목 `report.py:181` `it["text"].strip()[:MAX_ITEM_TEXT]`(=240, `:142`) → "단기 FX 스와프(", "그러". (b) **리드** `report.py:184` `lead.strip()[:MAX_LEAD]`(=300, `:141`) → "…최근 5일간 코스피 지수가 하—"처럼 줄글 중간 절단. 둘 다 산문(문장)이라 문자수 하드컷이 끝을 못 맺는다.
- **고침**: ① 1차 = `build_section_prompt`에 "각 항목은 **예산 내 완결된 문장**으로"를 명시(LLM이 애초에 안 넘치게). ② 안전망 = 하드컷 대신 **문장 경계 컷**. cap은 토큰폭탄 방어 상한으로 유지하되(제거 아님), cap 초과 시 **cap 이내 마지막 문장 경계**에서 자른다.
- **경계 문자셋(리뷰 교정 — 내가 틀렸던 부분)**: 한국어는 **ASCII 마침표 `.`·`!`·`?`**로 끝난다 → 이것 + 전각 `。！？` + 줄바꿈을 경계로. **`·`(가운뎃점)은 병렬 구분자라 경계 아님**("반도체·전력·자동차" 중간 절단 금지). 말줄임 `…`는 경계 취급 가능.
- **무경계 폴백(리뷰 지적 — 미정의였음)**: cap 이내 문장 경계가 없으면 **마지막 공백(단어 경계)**에서 자른다 — 단어 중간·조사 중간·열린 괄호로 끝나지 않게. 그래도 없으면(공백 없는 초장문) cap 하드컷하되 그건 예외 경로로 로그.
- **불변식(테스트)**: 결과가 (a) 단어/토큰 중간에서 끝나지 않음, (b) 열린 괄호·구분자로 끝나지 않음, (c) 정상 완결문은 그대로 보존, (d) 빈 입력 방어. 순수 함수로 분리해 결정론 단위테스트. **cap 수치는 테스트에 박지 말고**(매직넘버 금지) 경계·무결성 불변식으로 검증.
- **적용 범위 = 산문 필드(항목 text + lead) 둘 다.** 같은 경계-컷 순수 함수를 재사용. **headline만 제외**(짧은 명사구 제목 '삼성·SK 반도체 훈풍'류라 종결부호 없어 경계룰이 오히려 `·`에서 자르거나 빈 제목을 냄 — 리뷰 지적, cap 100도 거의 안 걸림). 즉 리뷰의 '리드 무버그' 가정을 사용자 실측(리드 잘림 화면)으로 뒤집되, 명사구인 headline 확장만 회피.

## WB2. 리드 → 핵심 합성 불릿 (버리지 않고 짧게) — 사용자 확정
- **문제(사용자)**: 리드(AI 요약)가 아래 섹션과 사실이 겹쳐 중복으로 읽히고, 긴 산문이라 읽기 힘들다. **버리진 않는다** — 리드의 고유 역할은 섹션(국면별 목록)이 못 주는 **엮인 현재-상태 서사(반전·인과)**다.
- **고침**: 리드를 **긴 산문 → 짧은 합성 불릿 2~3개**로. 프롬프트 지시 = "**섹션 항목 재요약 금지**, 현재-상태 + 핵심 반전을 한 단계 위에서 합성한 2~3 불릿(섹션 불릿과 같은 층위로 복붙하면 중복). '딴 거 안 읽어도 이 2~3줄'인 큐레이션 TL;DR."
- **리드 스키마 계약(W_web과 고정·frozen)**: `lead`를 **짧은 문자열 배열(≤3, 각 불릿)**로 산출. W_web은 이를 불릿으로 렌더. **하위호환**: W_web은 `lead`가 문자열(구형)이면 산문 폴백, 배열이면 불릿 — 배포 순서 무관하게(graceful). 각 불릿에도 WB1 문장경계 컷 적용(중간 절단 금지).
- **테스트**: lead가 ≤3 항목·각 항목 완결·빈 방어. 개수는 상한 불변식(매직넘버 아님).

## WB4. 그룹 순서 (config SSOT)
- `topics.yaml` 렌즈 등장 순서를 조정해 조립 순서 = **주식(한국·미국) → 금리·채권(한국·미국) → 나머지**. (라이징 최상단은 web 규칙=W_web.) 순서 SSOT는 topics.yaml 단일 출처(`report_groups`가 도출), 하드코딩 복제 금지.
- **테스트**: 순서를 바꾸면 순서를 pin한 기존 테스트가 있으면 함께 갱신(리뷰 지적 — '회귀 0'은 계약 shape 기준이지 출력 순서는 의도 변경). `report_lens_ids`/`report_groups` **계약(자산 렌즈 정확히 1그룹·누락 없음)은 불변**, 순서만 변경. 금리·채권 그룹(`kr_rates`·`us_rates`, report_group="금리·채권")이 실재함(topics.yaml) — 대상 존재 확인됨.

## 통합/배포 (오케스트레이터가 머지 후)

## 범위 밖
2층 프레임 재정의(Round 2·frames.py). 글로벌 프레임(화면만 숨김=W_web, 백엔드 무변경 — _market 생성·주입 유지). web 렌더. divergence/conviction 계산.

## 리스크/주의 (주입 gotchas)
- **매직넘버 금지**: cap을 경계룰로 감싸고, 테스트는 불변식(무결성·경계)으로. 240을 기대치로 박지 말 것.
- **비파괴**: DB·스토리·리포트 문서 계약 불변. 생성/검증/리뷰 실패는 기존 유지(fail-soft) 계약 유지.
- Docker 전용 테스트·로컬 python 없음. 머지·배포는 오케스트레이터(브랜치까지만).
- frames.py·web 절대 미변경(각각 Round 2·W_web 소유).
