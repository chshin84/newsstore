# 리포트 탭 — 섹터 risk/기대 프레임 합성 보고서 — 설계 (린 v1)

성격: 분석 레이어 위 응용 1차(섹터 의사결정 보조). 토대: Phase 1 렌즈 · Phase 2 델타 · Phase 3 score · stories. 결정 출처: 메모리 `report-tab-design`. 상위: `docs/analysis-design.md` · 계약: `docs/firestore-contract.md`. **이 문서는 3렌즈 리뷰 후 "빼기(SUBTRACT)"로 린하게 재작성되었고, 2026-07-01 사용자 확정 결정(§결정)을 본문 전체에 반영해 2026-07-03 재개정되었다. §결정 블록이 SSOT이며 본문과 어긋나면 §결정이 이긴다.**

## 1. 목표 / 본질
스토리를 **섹터별 의사결정 보조 보고서**로 합성한다. 본질: 시장의 집단적 고민을 정제해 엿듣고, 사용자가 *"조정이냐 국면 전환이냐 / over·undervalue냐"*를 판단할 재료를 깐다.
- **리포트는 판정하지 않는다 — 프레임(재료)만.** 매수·매도 콜 없음. over/under는 사용자가 가격을 겹쳐서(판정 자동화는 후속 아키타입 레이어).
- **이슈 중심, 가격 데이터 불요.** 리포트는 이슈·리스크·기대·센티먼트만.

## 2. 분석 모델 — 세 축 프레임 + 뉴스 대조 (결정⑧)
토픽마다 standing 프레임 3축: **risk(아킬레스건/실질 리스크**, 하방**)** + **premium(기대/컨센서스**, 상방 — *내러티브상 기대*, 가격 미사용**)** + **watchpoints(주시 포인트** — 실적 발표·FOMC·정책 시한처럼 극을 트리거할 수 있는 **예정된 관찰 지점**, 판정 아님**)**. 72h 뉴스를 프레임에 대조: 두려움을 트리거한 이벤트? 기대를 트리거/확인한 이슈? 인과 귀속("누가 뭐라 했고→어떤 우려/기대를 건드렸다"). "영향"=우려/기대 내러티브 영향(가격 아님).
- **델타 중심**: 힘이 모이는 곳=델타 있는 뉴스. 델타가 어디 볼지를, 실질-괴리가 판단 재료를.
- **단극 허용**: `risk`(지정학) 등 premium 극이 N/A인 렌즈는 단극 프레임(아킬레스건만).
- 명명 주의: 프레임 축 **watchpoints**는 렌즈 type **watch**(watch_samsung 등 개별종목)와 별개 식별자다 — 충돌 방지를 위해 축 이름을 watchpoints로 확정.

## 3. 프레임 출처 — 전용 프레임 패스가 유지 (결정⑧ — 결정④ 일부 개정)
[risk(아킬레스건)/premium(기대)/**watchpoints(주시 포인트)**] 프레임은 **전용 프레임 패스**가 유지한다(1×/일, 리포트 패스 전 실행). 입력 = **어제의 프레임(이월)** + 그 섹션의 누적 스토리(**입력 캡 `FRAME_MAX_INPUT_STORIES`** — 프레임 패스가 새 토큰 폭탄이 되지 않게), 출력 = 갱신된 `frames/{lens_id}`. 사람이 편집하는 `config/theses.yaml`은 폐기 유지(결정④의 "AI 자동" 정신 — 수동 시드가 필요하면 프레임 패스 프롬프트 힌트로, 코드/설정 아님).
- **리포트 콜은 프레임을 입력으로만 받는다**(그날 뉴스에서 역산하지 않음) — 프레임 산출과 트리거 판정이 다른 시점·다른 콜로 분리되어, 결정⑥이 수용했던 **자기충족 회로가 구조적으로 끊긴다**. "미발생" = standing 프레임 극 중 72h 트리거 없는 것 — 이월 덕에 **런 간 비교 가능한 신호**가 된다("3일째 미발생"이 의미를 가짐). §2의 "구조적·준정적" 성질 복원.
- **극 상한 `FRAME_MAX_POLES`(=5/축, 결정⑧)** — **매 런 전체 극 재심**: 프레임 패스가 이월된 극 각각을 유지/수정/탈락으로 그때그때 판단한다(시간·나이 기반 자동 밀어내기 없음 — 오래됐어도 유효한 아킬레스건은 남는다). 상한 없으면 프레임이 단조 증가해 리포트 입력 폭탄이 된다. **재심 계약(이월 관성 완화)**: 프롬프트가 유지 판단에도 "최근 근거 유무"의 명시를 요구하고, §5의 diff-grounding 리뷰가 무근거 유지 극을 지적하면 반영한다 — 상한 미만이라 경쟁 압력이 없을 때 낡은 극이 관성으로 눌러앉는 것을 막는 유일한 장치이므로 계약으로 박는다.
- **스냅샷 이력**: 갱신 시 이전 프레임을 `frames_history`에 보관(additive) — "프레임이 어제와 달라진 점"(delta_since_last)의 토대.
- **watchpoints 축은 판정이 아니다** — 실적 발표·FOMC·정책 시한처럼 **극을 트리거할 수 있는 예정된 관찰 지점**만(§1 "판정하지 않는다" 유지). 예: 반도체 risk="빅테크 capex 감속 시그널", watchpoint="메타 실적(하이퍼스케일러 약한 고리)".
- **한계(정직)**: 프레임 자체도 LLM이 뉴스 코퍼스에서 도출하므로 완전 독립 기준선은 아니다. 다만 같은 콜 내 역산→판정 순환(결정⑥ critical)은 구조로 제거됐고, 남는 위험은 프레임 품질(LLM 판단)·이월 관성(낡은 극이 오래 버팀 — 교체식 상한이 완화)이다.
- 섹터 어휘 = `config/topics.yaml` 렌즈(SSOT). **리포트 대상·그룹·앵커는 §3.5가 규정한다**(watch·sector 렌즈 제외 15종 — 이 줄의 과거 "모든 도출 렌즈가 대상" 서술은 결정⑦로 폐기). "thesis 없는 렌즈 skip" 규칙도 폐기 — 프레임 패스가 모든 대상 렌즈의 프레임을 유지하므로 skip 사유가 없다.

## 3.5 리포트 대상·그룹 (결정⑦ — 2026-07-03)
- **생성 단위 = 렌즈당 1리포트**(topics.yaml 도출 SSOT 유지 — 손 고른 리포트 목록 하드코딩 금지). 대상 = watch·sector 외 렌즈 전부: kr/us_equity·kr/us_rates·kr/us_econ·kr/us_policy·fx·kr_realestate·oil_energy·precious_metals·commodities·crypto·risk (15종).
- **sector_* 렌즈는 리포트를 만들지 않는다**(파편화 방지 — 분류·스토리 카드·층화 쿼터용으로만). 대신 §4의 섹터 층화 쿼터가 **한 테마의 독식을 상한(cap)으로 막는다**. cap은 조용한 섹터를 채워주지 않는다(fill 아님) — top-K 후보에 없는 섹터는 리포트에 안 나오며, 이는 수용된 한계다.
- **UI 섹션 앵커 = 그룹**(단일 문서 — 결정⑧): topics.yaml 렌즈에 `report_group` 속성(주식/금리·채권/경제/정치·정책/환율/부동산/원자재/코인/리스크)을 더해 도출 — 원자재처럼 1그룹:N렌즈는 그룹이 흡수하고, 프레임·검증·실패 배지 입도는 렌즈 단위로 유지된다.
- **급부상(rising) 리포트 1종**: 렌즈가 아니라 **결정론 선정** — 이미 저장되는 `developments[].delta_time`의 최근 24h 밀도(velocity 근사) 상위이면서 **다른 리포트의 top-K에 등장하지 않은** 스토리 집합을 입력으로. 여기서 top-K는 §4의 **결정론 입력 선정 집합**이다(LLM이 인용한 story_ids가 아님 — LLM 출력에 걸면 결정론 주장이 무너진다). 스냅샷 인프라 불요(리뷰 V4 수렴). LLM 선정 아님 — 원안 "rising meme"의 상시 감시 의도를 전용 리포트로 보존.
  - **한계(정직)**: 밀도는 신규성이 아니다 — 오래된 대형 스토리가 24h 내 이벤트율을 유지하면 급부상으로 오탐될 수 있다(진짜 변화율은 스냅샷 이력이 생기는 후속에서). 렌즈 추가/제거가 "top-K 미등장" 멤버십을 바꾸는 결합도 수용된 특성이다.

## 4. 생성 파이프라인 — 단일 리치 콜 (다단계 체인 X)
다단계 chained 합성은 환각 전파+비용폭증이라 v1에서 **제거**(리뷰 반영). 중간 자산(클러스터·score·델타·렌즈) 재사용 — 리포트는 stories의 또 다른 렌더러(기존 per-story `article` 패스와 **별개**: 그건 스토리 1개 보고서, 이건 렌즈 레벨 합성).
```
(선행, 1×/일) 프레임 패스 — 섹션(렌즈)별 1콜: 어제 frames/{lens_id}(이월) + 누적 스토리(캡)
   → 전체 극 재심(유지/수정/탈락, 축당 5) → 결정론 검증(스키마·상한·중복)
   → **diff-grounding 리뷰**(신규/수정 극만 — §5 표) → 갱신 frames/{lens_id} (+frames_history 스냅샷)
   → 실패(생성·리뷰 기각) 시 어제 프레임 유지(이월 폴백 — updated_at 미갱신으로 관측)
(런당 1회) 매크로/교차자산 백드롭 — 채권·순환매·원자재·매크로를 1회 합성(cross-lens는 여기 1곳만).
   → 결정론 검증 + grounding 리뷰 1콜(§5 표 — 16개 섹션의 공통 입력이라 오염 전파 지점).
   단일 문서의 **서두**로 쓰이며 `reports/_backdrop` 별도 문서에 저장(섹션 문서에 중복 저장 안 함).
   실패 시 서두 생략 + 섹션 콜에 미주입(degrade — 파이프라인 계속).
섹션별(렌즈당 1 섹션):
  standing 프레임(frames/{lens_id}) + 렌즈의 72h stories 중 [delta·impact 상위 K건 하드캡,
  주식 렌즈는 섹터 층화 cap] + 백드롭
   ↓ LLM 1콜(구조화 출력) → {headline, lead,
       sections[risk 트리거 / premium 트리거 / 미발생 / watch], 각 섹션 항목 = {text, story_ids[]}}
     (프레임은 **입력** — 산출 아님, 결정⑧. 트리거 주장은 story_ids 인용 필수 — B)
   ↓ 검증 — 결정론(인용 story_id가 입력 stories에 실재 — 환각 id는 항목 드롭 / 언급 티커·엔티티가
       입력 출처에 존재) → LLM 리뷰 1콜(grounding+fit)
(마지막) 급부상 — **전 렌즈의 top-K(위 결정론 입력 선정 집합) 확정 후** 도출(순서 의존 — §3.5),
  선정 스토리 집합으로 같은 단일 콜·검증. 출력: reports/rising
(조립 — LLM 0콜, 결정론) **단일 데일리 리포트** = 백드롭 서두 + 자산군 섹션들 + 급부상 말미.
  교차 링크 = 같은 스토리가 여러 섹션에 인용된 지점(다중 인용 결정론 — "관련: §채권").
출력: reports/{lens_id} 섹션 단위 저장(검증·배지 입도 유지 — 한 섹션 실패가 문서 전체를 오염 안 함),
  렌더가 단일 문서로 조립(캐시; UI 직접 read)
```
- **입력 하드캡 `REPORT_MAX_STORIES`**(예 K=15) — 선정 랭킹은 **UI와 동일한 `storyRank`(impact×신선도, 신선도=developments[].delta_time 최신성 — web/index.html 순수함수와 같은 정의)**로 결정론 재현 가능하게 못박는다("delta·impact 상위"의 delta는 이 delta_time 신선도다 — 스토리 레벨 delta 필드는 없음). 한 렌즈 클러스터가 수백 건까지 부푸는 실측(analysis-design §1) 대비 토큰 폭탄 차단(품질·지연 목적 — §8). 별도의 런당 토큰/콜 예산 상한은 두지 않는다(결정② — 비용 상한 없음).
- **섹터 층화 쿼터(주식 렌즈 한정)**: top-K 선정 시 스토리의 `sector_*` 라벨로 층화(같은 섹터 최대 N건) — 한 테마(반도체 443건 실측)가 상위를 독식해 "주식이 섹터를 깊게"가 붕괴하는 것을 결정론으로 방지(리뷰 V1 수렴). 새 인프라 없음(sector 라벨은 이미 멀티라벨로 존재).
- **빈 리포트 가드**: 스토리가 `REPORT_MIN_STORIES`(예 2 — 사이트 스토리 표시 기준 count>=2와 동일 발상) 미만인 렌즈는 생성 콜 스킵, UI "아직 생성 전" 강등. 임계는 상수로 박아 재량을 없앤다. **의도적 미생성과 생성 실패를 구분**해 §5(b) 갱신 지연 라벨 오발동을 막는다(리뷰 V4 수렴).
- 출력은 **구조화 슬롯**(자유 내러티브 최소화 — 판정 누출↓). watch-list(개별종목 나열)는 v1 제거(프레임만 일관·"개별종목 콜 금지"와 충돌 회피). delta_since_last도 v1 제거(이전 스냅샷 보관 필요 — YAGNI).
- **모델**: `gemini-3.5-flash` — env `GEMINI_MODEL`로 주입(결정①, 하드코딩 금지). incremental 아님 — **per-run 전량 재생성**.

## 5. 검증 레이어 (`domain-llm-runtime` — 콜별 리스크 비례 배치)

| 콜 | 리스크 | 결정론 검증(항상, 코드) | LLM 리뷰 | 실패 거동 |
|---|---|---|---|---|
| 프레임 갱신(≤15) | 3 — 하류 16콜의 입력 + **이월로 내일까지 전파** | 3축 스키마·축당 ≤5·극 길이·중복 | **grounding, diff만** — 신규/수정 극의 스토리 근거만 검증(유지 극은 과거 검증분·재심 계약). 변경 없으면 리뷰 0콜 | 어제 프레임 유지(이월 폴백), `updated_at` 미갱신 → UI "프레임 갱신 지연" |
| 백드롭(1) | 3 — 16개 섹션의 공통 입력(오염 전파) | 스키마·길이·티커 존재 | grounding 1콜 | 서두 생략 + 섹션 콜 미주입(degrade) |
| 섹션 리포트(≤16) | 4 — 사용자 노출·판정 경계 | 스키마·**story_ids 실재**·**트리거 극 id가 standing frame에 실재**(프레임이 입력이 되며 가능해진 체크)·티커 존재·길이 | grounding+fit 1콜(과인용 관련성·매수매도 금지·스타일) | (a)(b) 아래 |
| 섹션 리뷰 콜(≤16) | 리뷰 자체 | verdict 스키마 | 없음(리뷰의 리뷰 = 무한 회귀. 집계는 결정론 함수) | 리뷰 콜 실패 → `passed=false`+notes="리뷰 불가"(통과 위장 금지) |
| 급부상 선정·조립 | 0 — LLM 아님 | 순수함수+테스트 | — | — |

- 모든 콜 공통(비기능): `call_with_retry`(지수 백오프·비일시적 즉시 실패)·timeout·None/비객체 가드(`_json_object_or_none`)·LLMError 구조화·콜수/지연/실패율 로깅·키 비노출.
- *한계(정직)*: 동급 모델 자기검증 + 결정론은 엔티티·story_id **존재만** 봄 → **가짜 인과 연결은 못 잡음**. 그래서 v1은 개방형 교차자산 인과(step2)를 빼 그 표면을 줄였다. **B 특유의 추가 표면**: 인용을 게이트로 강제하면(§4) 모델이 게이트 통과용으로 한계적으로만 관련된 story_id를 붙이는 **과인용** 유인이 생기고, 결정론은 실재만 봐서 못 거르며, §7이 인용 스토리를 카드로 embed하므로 잘못된 인용이 '증거'로 시각 승격될 수 있다 — 완화는 리뷰 콜의 grounding(관련성) 항목.
- **실패 거동(결정③ = 경고 라벨 노출)**: **(a) 산출물 있음**(생성 성공·리뷰 실패) — 저장 + `review.passed=false`, UI "검증 실패" 배지. **(b) 산출물 없음**(생성 콜 실패) — 기존 문서 유지 + `generated_at` 기대 주기(1일) 초과 시 "갱신 지연" 라벨. **(c) 프레임 패스 실패** — 어제 프레임으로 리포트 진행(이월 폴백), `frames.updated_at` 기대 주기 초과 시 UI 섹션 머리에 **"프레임 갱신 지연"** 표시(런간 신호 '3일째 미발생'의 전제인 프레임 현행성이 조용히 낡는 것 방지).
- **버전 정합**: 섹션 리포트 저장 시 참조한 프레임 판(`frame_updated_at`)을 기록 — UI 섹션 머리의 현행 프레임과 본문이 참조한 판이 다르면(프레임은 갱신됐는데 리포트가 구판이면) 표기.

## 6. 데이터 모델 (additive·비파괴 — firestore-contract 등재 필요)
- **`frames/{lens_id}`**(신규 컬렉션, 결정⑧): `{risks[], premiums[], watchpoints[], updated_at, model}` — 프레임 패스 단독 writer, 리포트 패스·UI reader. 갱신 시 이전 판을 **`frames_history/{lens_id}/{date}`**에 스냅샷(additive — 프레임 델타의 토대, **v1부터 축적**).
- **`reports/{lens_id}`**(신규 컬렉션): `{topic, headline, lead, sections[{name, items[{text, story_ids[]}]}], frame_updated_at, generated_at, model, review{passed,notes}}` — 프레임은 frames 컬렉션으로, 백드롭은 **`reports/_backdrop`**(런당 1회, 단일 문서 서두의 출처 — 섹션 문서에 중복 저장 안 함)으로 분리(결정⑧). `frame_updated_at` = 이 섹션이 참조한 프레임 판(§5 버전 정합). **public read**(UI 직접). report 패스 writer. 급부상은 `reports/rising`(같은 스키마 — "급부상 스토리" 단일 섹션 + 선정 기준 명시 슬롯).
- stories(렌즈·risk·impact·developments·delta) 재사용 — 신규 필드 없음.
- **계약 등재(plan 작업)**: `reports` 스키마·writer/reader·**보안규칙(public read)**을 `firestore-contract.md`에 추가(드리프트 가드 대상). per-run 전량 재생성이라 *_count incremental 가드 없음(통째 덮어쓰기).

## 7. UI — 리포트 탭 (B: 스토리-그라운디드, 단일 문서 — 결정⑧)
- 새 탭 `리포트` = **단일 데일리 문서**. 섹션 네비(앵커) = topics.yaml `report_group` 도출(§3.5 — 도출 규칙이 SSOT, 손 목록 금지) + **급부상 앵커**(도출 규칙의 유일한 명시 예외 — `reports/rising` 존재 시 노출). 렌더 = 백드롭 서두 → 그룹 순 자산군 섹션(reports/{lens_id} 조립) → 급부상 말미.
- **섹션 머리에 standing 프레임 표시**: frames/{lens_id}의 risk/premium/watchpoints 극 요약 — "미리 준비된 것"이 사용자에게 보이고, 본문 트리거 대조가 그 극들을 참조한다. `frames.updated_at` 기대 주기 초과 시 "프레임 갱신 지연", 본문 `frame_updated_at`과 현행 프레임 판이 다르면 불일치 표기(§5).
- **교차 링크(결정론)**: 같은 스토리가 여러 섹션에 인용되면 "관련: §채권" 링크 — LLM 인과 아님, 다중 인용 데이터가 근거.
- 급부상 렌더: "급부상 스토리" 단일 섹션(선정 기준 표기 + 항목별 카드 embed).
- 렌더: headline → lead → 구조화 섹션(아킬레스건 트리거/기대 트리거/미발생). **섹션 항목마다 인용 story_ids의 스토리 카드(델타 타임라인·미터)를 하위 컴포넌트로 embed** — 기존 스토리 카드/디테일 재사용. 같은 스토리가 여러 섹션에 인용되면 **카드는 1회, 나머지는 참조 배지**(dedup).
- 생성시각·"가격 미반영(이슈 중심)" 표기. `review.passed=false`면 **"검증 실패" 배지**(결정③). 상태 3구분: 정상 / **아직 생성 전**(스토리 부족 스킵 — §4 빈 리포트 가드) / **갱신 지연**(§5(b) — 기대 주기 초과). 순수함수(node): 그룹·앵커 도출, 카드 dedup, 상태 구분.

## 8. 스케줄 / 운영
