# 데이터 소스 — newsstore가 받는 모든 데이터

이 문서는 newsstore가 현재 수집하는 데이터의 스냅샷이다. newsstore는 **뉴스 수집 전용**이라 분석·LLM 레이어가 없고, 수집한 원본을 Firestore에 저장한 뒤 임베딩 벡터만 부수적으로 산출한다.

수집 경로는 세 가지다.

- **RSS 피드** — 등록된 공개 RSS를 주기적으로 폴링한다. 활성 피드 목록과 개수의 SSOT는 `config/feeds.yaml`이다.
- **FMP 뉴스 API** — Financial Modeling Prep의 뉴스 파이어호스 6개 엔드포인트를 통합 수집 잡이 실행될 때마다 재스캔한다.
- **네이버 검색 뉴스 API** — 키워드별로 한국 뉴스를 검색해 수집한다. 활성 키워드의 SSOT는 `config/naver_news.yaml`이다.

수집 원칙은 "본문만"이다. 제목과 함께 요약이나 전문이 실제로 오는 소스만 활성화하고, 제목만 오는 헤드라인 전용 피드는 제외한다. 임베딩 품질과 다운스트림 재사용이 본문 유무에 좌우되기 때문이다.

## 활성 RSS 피드

각 피드의 `body_mode`는 본문이 오는 방식을 뜻한다. `full`은 전문(content:encoded), `summary`는 요약 스니펫이다. 헤드라인 전용(`headline`)은 이번 가지치기로 모두 제거했다. 활성 피드 목록과 개수의 SSOT는 `config/feeds.yaml`이며, 아래 표는 그 내용을 계열별로 묶어 읽기 쉽게 안내한 것이다.

## FMP 뉴스 API

Financial Modeling Prep의 뉴스 파이어호스를 통합 수집 잡이 실행될 때마다 고정 3일 lookback으로 전량 재스캔한다. 소스별 주기 판정(`poll_minutes`·`is_due`)은 2026-07-23 수집 파이프라인 통합에서 제거됐고, 실행 주기는 Cloud Scheduler 설정이 SSOT다(`docs/operations.md`의 리소스 표를 보라). 커서 없이 매번 재스캔하고 URL 기반 id로 중복을 걸러 멱등하게 적재한다. API 키는 백엔드 전용 비밀로 헤더에만 싣는다.

| 엔드포인트 | 내용 |
|---|---|
| `stock-latest` | 미국 주식 뉴스 |
| `press-releases-latest` | 기업 보도자료 |
| `general-latest` | 종합 금융 뉴스 |
| `forex-latest` | FX 뉴스 |
| `crypto-latest` | 크립토 뉴스 |
| `fmp-articles` | FMP 자체 분석 기사 |

한국 시간으로 오전 7시부터 9시까지는 FMP 패스 전체를 건너뛴다. 같은 FMP API를 쓰는 별도 프로세스가 그 시간대에 호출하기 때문에 쿼터가 겹치는 것을 피하려는 조치다. 경계값의 SSOT는 `config/fmp_news.yaml`의 `blackout_start_hour`와 `blackout_end_hour`이며, 판정은 시작 시각을 포함하고 종료 시각을 제외하는 반개구간으로 한다. 블랙아웃에 걸린 패스는 요청도 저장도 하지 않는 순수 no-op이라 `feed_state`도 갱신하지 않는다. 따라서 이 시간대에 FMP가 아무것도 하지 않은 것은 수집 실패가 아니라 의도된 스킵이다.

## 네이버 검색 뉴스 API

네이버 검색 API로 키워드별 한국 뉴스를 검색해 수집한다. 수집 주기는 통합 잡의 스케줄러 주기를 그대로 따르며 소스별 due 체크가 없다. 요청당 100건(config의 `display`)을 최신순으로 받는다. 응답의 `originallink`를 우선 URL로 쓰고 없으면 네이버 재작성 `link`로 폴백하며, 제목과 요약의 `<b>` 하이라이트와 HTML 엔티티를 제거한다. 클라이언트 ID와 시크릿은 백엔드 전용 비밀로 헤더에만 싣는다.

키워드는 카테고리가 아니라 신호 높은 전문검색어로 큐레이션한다(예: 코스피·HBM·SMR). 그 단어가 실제로 들어간 기사만 좁게 잡으려는 것이며, 전체 목록은 config를 보라.

## 처리 파이프라인

세 경로로 들어온 원본은 같은 파이프라인을 거쳐 `items` 컬렉션에 저장된다.

RSS·네이버·FMP 세 경로는 통합 수집 잡 하나 안에서 병렬로 실행되고, 같은 마감 시각을 예산으로 공유하며 각 경로가 그 예산을 스스로 지킨다. 예산의 SSOT는 `src/newsstore/entrypoints/run_collect_all.py`의 두 상수이며, `DEADLINE_SECONDS`는 각 경로가 스스로 지키는 1단 예산이고 `BACKSTOP_SECONDS`는 오케스트레이터가 결과를 기다리다 끊는 2단 백스톱이다. 어느 경로든 예산을 넘기면 남은 대상을 처리하지 않고 중단하며 잡 전체를 실패로 기록한다. 다만 그때까지 저장된 항목은 루프 안에서 그때그때 커밋했기 때문에 그대로 남는다. 따라서 `config/feeds.yaml`의 피드 나열 순서가 예산이 소진됐을 때의 처리 우선순위가 된다.

- **URL 기준 중복 제거** — URL(없으면 guid, 그것도 없으면 제목)로 만든 안정적 id로 같은 기사를 한 건으로 접는다. 같은 뉴스가 URL만 달라 여러 건 들어오는 경우의 제목 정규화 접기는 저장이 아니라 사이트 뷰에서 비파괴로 처리한다.
- **kind 분류** — 비-LLM 규칙 필터가 스팸(집단소송 보도자료 등)·스포츠·다이제스트를 키워드로 분류해 표시한다. 원본은 지우지 않고 숨김 표시만 한다(비파괴).
- **임베딩** — `kind == story`인 기사를 gemini-embedding-001로 768차원 임베딩한다.
- **`item_vectors` 저장** — 벡터를 원본과 같은 만료 시각으로 저장한다(고아 벡터 방지).
- **60일 TTL** — `items`와 `item_vectors`의 각 문서에 `expire_at`(수집 시각 + 60일)을 걸어 만료시킨다. `feed_state`에는 TTL을 걸지 않는다(폴링 커서가 유실되면 증분 수집이 어긋난다).

## 차단·미작동·제거된 소스

단순 삭제가 아니라 이유를 남긴다. 같은 소스를 다시 시도하거나 대체 경로를 찾을 때 이 기록이 필요하기 때문이다. 아래 발견·정리는 모두 2026-07-19 기준이다.

- **Benzinga (16개 피드)** — 2026년 6월부터 피드 item이 0으로 떨어져 사실상 죽었다. 경로 자체를 폐기하고 활성 목록에서 제거했다.
- **NPR 경제 (1개 피드)** — RSS 자체는 살아 있어 브라우저로는 정상적으로 읽히지만, Cloud Run 데이터센터 IP를 HTTP 403으로 차단해 수집이 되지 않는다(feed_state 연속 실패 13회 기록). 브라우저 UA를 이미 쓰고 있으니 UA 문제는 아니다. 클라우드 IP가 원인이라 로컬 수집 환경에서는 되살릴 수 있다.
- **제목 전용 9개 피드** — 응답은 정상이나 per-item 본문이 없어 제목만 오는 피드를 제거했다: 한경 구글뉴스 우회(gn_hankyung), Yahoo Finance, Seeking Alpha, Investing FX(investing_fx), Investing 채권(investing_bond), ECB, 루머·반도체 구글뉴스(gn_rumor·gn_kr_chips), Reuters 구글뉴스 우회(reuters_top).
- **WSJ와 FT (되살림)** — 한때 클라우드 IP 차단과 제목 전용을 이유로 제거했으나, 2026-07-19 재검증에서 본문이 오는 다른 엔드포인트를 찾아 각각 5종씩 되살렸다. 지금은 제거 대상이 아니라 활성 피드이며, 자세한 경위는 위 "미국·글로벌 금융 종합"을 보라.
- **이전에 주석으로만 남아 있던 19개 후보** — 프로빙에서 HTTP 403·404를 받거나 빈 피드였던 후보들이다. 이번에 config에서 완전히 삭제하고 사유를 이 문서로 옮겼다. 한경 직접 RSS 6종(클라우드 데이터센터 IP 403), 인포맥스 기고 섹션(빈 피드), Benzinga 스몰캡(빈 피드), BIS 보도자료·BLS·NBER·IMF·CFR·IEA·OPEC·Kitco·KCIF·한국은행·Bloomberg 그린 등이 여기에 해당한다.
- **FMP 뉴스** — 코드는 있었으나 수집 Job이 배포되지 않아 한동안 0건이었다. 이제 Job이 배포되어 수집된다.

한경 본문 스크랩(hankyung.com `.article-body` 셀렉터)도 한경 소스가 사라지면서 함께 비활성화됐다. 한경이 유일한 대상이었던 탓에 현재 화이트리스트(`src/newsstore/collect/body_fetch.py`의 `BODY_SELECTORS`)가 비어 있고, 그래서 본문 스크랩 기능 전체가 휴면 상태다 — 어떤 소스에 대해서도 기사 페이지를 따로 긁지 않으며 본문은 오직 피드가 주는 만큼만 쓴다. 본문 스크랩이 필요한 소스가 다시 생기면 `body_fetch.py`의 셀렉터 맵에 등록한다.
